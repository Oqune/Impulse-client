# Policies — жёсткие правила исполнения (Impulse)

Этот файл — контракт. Агент обязан ему следовать на каждой задаче.

## 1. Коммиты
- Только **Conventional Commits**: `feat:` `fix:` `docs:` `refactor:`
  `style:` `test:` `chore(release):`.
- Коммиты **атомарные** (одна логическая правка = один коммит).
- Сообщение на английском, описательное. Без эмодзи.
- Никогда не коммить: секреты, билды (`build/`, `*.apk`), логи,
  `.superpowers/`, `.kilo/`, `.idea/shelf/`, `docs/audit/`, `config.toml`.

## 2. Ветвление (Trunk-based)
- `master` — всегда стабильная, развёртываемая.
- Фича/фикс → короткая ветка `feat/<topic>` / `fix/<topic>` → merge в master.
- Не держать висячих веток «на потом» (как было с `v26-wip`).
- Удалять слитые/осиротевшие ветки сразу.

## 3. Тестирование (Test-gate)
- Перед коммитом: сборка + юнит-тесты ОБЯЗАТЕЛЬНЫ.
  - client: `./gradlew testDebugUnitTest`
  - server: `cargo test` + `cargo clippy -- -D warnings`
- Если тесты не проходят — не коммитить, чинить.
- Новая логика (особенно crypto/auth/sync) — с тестом.

## 4. Crypto & протокол (критично для E2EE)
- Любые правки ML-KEM/ML-DSA/AES-GCM/Argon2id — **только через SPEC + аудит**.
- НЕ менять wire-протокол (опкоды 0x01–0x0C) без синхронного изменения
  client **и** server + отдельного SPEC.
- Параметры шифрования — не ослаблять (Argon2id: m=47104, t=3, p=1 — OWASP).

## 5. Изоляция ИИ-артефактов
- Артефакты агентов (`.superpowers/`, `.kilo/`, `review-*.diff`, `.idea/shelf/`)
  **никогда не попадают в VCS** (уже в `.gitignore` обоих репо).
- Аудит-отчёты (`docs/audit/`) — локально, не в git, не в OKF.

## 6. Деплой
- Только через `docs/policies/deploy.md`. Ручной деплой без скрипта — нет.
- Секреты (`config.toml` с Argon2-hash) не светить в логах/чатах/OKF.

## 7. Безопасность логов
- Не логировать: пароли, ключи, raw auth-пакеты (hex-dump удалён в аудите).
- Логировать только длины/метаданные, не содержимое.
