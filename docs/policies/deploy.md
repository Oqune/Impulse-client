# Политика деплоя Impulse Server (Windows)

Целевая машина: Windows-ПК (z690d4, 192.168.1.50) — «второй сервер».
Порты проброшены, `config.toml` (Argon2-hash пароля + серты) на месте.

## Текущий ручной процесс (до автоматизации)
1. На ПК: `cd server && cargo build --release`
2. Скопировать `target/release/impulse-server.exe` + `config.toml` на Windows-сервер
   (в папку, где сервер запускается).
3. Перезапустить сервер (служба / скрипт / вручную).

## План автоматизации
Скрипт `deploy-server.ps1` (на ПК), делает:
1. `cargo build --release` (server).
2. Проверка, что бинарь собрался.
3. Копирование бинаря + `config.toml` на Windows-сервер (через SMB-шару
   `\\<SERVER>\Impulse` или локально, если ПК = сервер).
4. Перезапуск службы (через `nssm` или `schtasks`, т.к. systemd на Windows нет).
5. Health-check: подключение к порту 4433, лог старта.

## Правила
- ❌ `config.toml` с секретами НЕ в git, НЕ в OKF, НЕ в логах.
- ❌ Не деплоить без успешной сборки + `cargo test`.
- ✅ Деплой только через этот скрипт (не руками).
- ✅ Перед деплоем — коммит в master пройден (trunk-based).

## Открытые вопросы
- Служба сервера на Windows: через `nssm` (Non-Sucking Service Manager)?
- Триггер деплоя: локально на ПК или SSH с сервера oqune?
- Нужен ли rollback (хранить пред. бинарь)?
